# EVORA v1.3.4

- Windows desktop ChatGPT sign-in uses the system browser through a restricted native bridge, instead of relying on WebView pop-ups. Ordinary browser sessions retain their normal popup flow.
- Both Windows executables now embed the EVORA shield icon and product version metadata.
- The application header and favicon use the same shield artwork.
- Bundled Neo4j/Java from v1.3.2 is retained.

Validation covers URL restrictions, simulated browser/native authorization handoffs, protected credential/callback tests, frontend checks and native package smoke tests. Live authorization with the affected user's ChatGPT account still requires verification; this release does not assert provider consent succeeds for every account.

Callback failures now report a safe stage, HTTP status/known OAuth error, or clock/identity/network guidance, instead of hiding every failure behind one generic message. Tokens and provider descriptions are never printed in that message. TLS verification retains public roots and also loads Windows trusted system certificates. The affected account must retry to identify or verify resolution of its browser-side error.

The desktop also avoids occupied local ports and rejects readiness when its own backend has exited, preventing an old background server from being mistaken for the new build.
