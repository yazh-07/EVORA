# EVORA bounded task catalog

**Planning status:** every implementation row is Backlog unless `docs/ROADMAP.md` records an assigned branch and real verification. Published coordination-branch draft, not a running application. The entire initial proposal is fixed build scope, delivered in stages; the CSV tracer is not a reduced product. [`PROPOSAL.md`](PROPOSAL.md) preserves the source; [`PROPOSAL_TRACEABILITY.md`](PROPOSAL_TRACEABILITY.md) maps all numbered sections.

## Assignment rules

- One row is one bounded assignment, fresh session and short-lived `feat/<lowercase-id>-<slug>` branch/PR. A module is an accountability boundary, not an agent job. Split an overly broad implementation row into reviewed smaller slices without marking the parent complete prematurely.
- Four people each work on one module; one also coordinates integration alongside their module. Assignees remain TBD. No fifth person, personnel title or four-signoff ceremony is required. Help across boundaries is scoped and retains one accountable module interface.
- Dependencies mean real integration prerequisites. Independent implementation against generated schema-derived fixtures/test doubles is allowed before producers land; disclose doubles and do not claim integrated completion until real merged producers pass.
- `specs/openapi.yaml` version 0.2.0 owns the same 25 operationIds and all wire schemas. Contract cells reference existing operations/schemas/internal policy, never authorize invented endpoints or enum values. Private provenance is internal, not an additional public API schema. Every UI row applies DESIGN.md accessibility, safe evidence/model-text rendering and no persistent bearer-token/original-evidence storage.
- Resolve only gates needed by the selected task (C-03 auth, C-04 format/failure limits, C-05 scoring, C-06 RAG/privacy). Review/setup and unaffected scoped work can proceed; neither a blanket stop nor a blanket all-clear is accurate.
- Coordinate scaffolding, migrations, spec/generated client changes and ledger edits. All tickets use one exact recorded common contract commit. Status, assigned module/person, allowed paths, fixtures, outputs and actual tests go in the PR and roadmap.
- Every producing row tests case isolation, declared 400 ApiError mapping and failure/partial-output behavior appropriate to that row; success must be read back from the real API/storage boundary. No fabricated runtime payloads or benchmark output.

Dependencies below are explicit task IDs; non-task format/model/privacy choices belong to the acceptance column and the decision queue. P08/P09/P10 require their own approved adapter/model/data-boundary decisions, and deterministic U10 requires authorized local retrieval/grounding policy, not G03's final generative provider choice. Full generation/verification U10B/U10C retains the G03 gate. G01/G01B/G01D must establish tested package versions in future skeleton/setup work; these documents do not claim anything is installed.
